# 禁止数值解验证链 — 第五验证链

## 1. 验证定义

本链验证输出是否符合**解析解原则**：不追求"数值评分"、"二元判断"、"模板化输出"，而是用"可能性"、"倾向性"、"合理性"表述。

## 2. 禁止模式

检测以下「数值解」违规模式：

| 模式 | 示例 | 判定 |
|:-----|:-----|:-----|
| 百分制评分 | "可信度85%"、"风险评分7.2/10" | ❌ 不通过 |
| 星级评定 | "⭐⭐⭐⭐"、"4.5星" | ❌ 不通过 |
| 二元好坏标签 | "好/坏/优/劣"无论证 | ❌ 不通过 |
| 全盘否定/全盘肯定 | "完全错误"、"完全正确"无条件 | ❌ 不通过 |
| 无依据的数值对比 | "比方案A好30%"无推导支撑 | ❌ 不通过 |
| 模板化填空 | "优点：_ 缺点：_" 无实质内容 | ⚠️ 警告 |

## 3. 通过标准

- ✅ 结论用「倾向于」「可能性较大」「在X条件下更合理」等表述
- ✅ 每个判断附带推理依据或条件说明
- ✅ 不轻易给出绝对化结论（"一定""绝对""肯定"）
- ✅ 承认不确定性（"尚无法确定""需要更多信息"）
- ✅ 复杂问题给出多角度分析而非单一评分

## 4. 验证流程

```
输入: 待验证文本

1. 扫描全文 → 检测是否有数值评分/二元标签/模板化输出
2. 发现违规 → 标注违规位置 + 违规类型
3. 未发现违规 → 通过
4. 仅警告 → 通过但附改进建议

输出: {pass: bool, issues: [{item, reason, fix}], conclusion: str}
```
